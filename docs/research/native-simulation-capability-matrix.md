# Native simulation extraction: capability matrix

- **Feature**: 009 (`specs/009-native-simulation-feasibility/spec.md`, FR-004, FR-010, FR-012)
- **Assessed**: 2026-11-08; companion of `docs/research/native-simulation-feasibility.md`, whose
  section numbers (§) and sources this file cites rather than restating them

One row per gameplay fact the platform wants, one cell per route. Every cell carries **one
availability class** (FR-004) and **one provenance category** (FR-012), then the evidence label.

Routes:

- **A** the game's own gRPC stream while the Windows client replays (CaptureAge's route, §3). Not
  run by this project. Its existence and the decoding of hit points, owner, type, position and
  deaths are **demonstrated by others** (cited code and a cited 2021 capture); every other field is
  **documented** from reverse-engineered model and proto definitions, and its fidelity is UNKNOWN
  because the published decoders resynchronise heuristically against a per-build model (§3.6).
- **B** `librematch/genie` (§4): read in code for build 158041 only, not run, unavailable for the
  project's builds.
- **CP** the state checkpoints the game writes into every recording (§6), **demonstrated here** on
  three recordings with tested code.
- **CL** the command log as the project reads it today (features 006 and 008), the baseline.

Availability classes: **direct** (a field of the exposed state), **snapshots** (from successive
snapshots), **events** (from an event stream), **inference** (needs additional inference),
**unavailable**. Provenance: `ENGINE_STATE`, `ENGINE_EVENT`, `DETERMINISTIC_DERIVATION`,
`COMMAND_LOG`, `INFERRED`, `UNAVAILABLE`. A raw checkpoint word is `ENGINE_STATE`; a fact derived
from one is `INFERRED` or `DETERMINISTIC_DERIVATION`, never `ENGINE_STATE`. Evidence labels:
**demonstrated here**, **demonstrated by others**, **read in code**, **documented**, **none**.

## Reading the matrix

- **No A cell was run by this project.** "Documented" means a field of a reverse-engineered model
  or proto definition cited in §3; "demonstrated by others" is limited to the stream's existence
  and the decoding of hit points, owner, type, position and deaths. A's exactness is the game's,
  but what a decoder reads out is as exact as its per-build model: UNKNOWN until run.
- **No B cell was run.** B is exact by construction for build 158041 and unavailable for the
  project's builds.
- **CP is the only engine-state source this project holds today.** Exact, coarse and partial: one
  corroborated word (the sum of stocks) and one identifier (the player id) per player every 500
  syncs, from the raw file, for the builds read (180059 and 185872; 188329 not read).
- **CL is intent.** Where a cell says "proof", feature 008 measured a later order that implies the
  earlier state.
- **No row is `ENGINE_EVENT` for this project today, and no row is exact per object.** The spec's
  five-scenario criterion (SC-003) is met for one scenario, resources as a sum (§7); the other nine
  depend on route A.
